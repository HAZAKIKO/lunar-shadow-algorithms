## 1. 先分清三类问题

"根据阳光阴影判断"这个说法包含了三个**完全不同**的问题。混淆它们是这个方向最常见的低级错误：

| 类别 | 输入 → 输出 | 典型用途 | 数学性质 |
|---|---|---|---|
| **A. 正演**（预测阴影） | DEM + 太阳位置 → 光照/阴影掩膜 | 算可观测性、规划观测窗口、判定 PSR | 确定性几何，可精确求解 |
| **B. 反演**（提取阴影） | 单张图像 → 阴影掩膜 | 做分割标签、检测障碍、发现坑 | 病态，需先验与消歧 |
| **C. 测量/重建** | 阴影 → 太阳角 / 物体高度 / 地表坡度 | 定标、无星历估计太阳方向、光度法补高程 | 部分病态（见 §8.5 方位简并） |

三者的关系是：**A 给真值，B 给观测，C 把两者连起来**。你的论文要做的通常是"用 A 合成数据训 B，用 C 做闭环验证"。

## 2. 四套坐标与方位角约定（最容易出错的地方）

我在实现这个模块时，**四个真实的 bug 里有三个是方位角符号写反**。所以这一节放在最前面。

### 2.1 图像坐标

`dem` 是形状 `(H, W)` 的数组，`dem[row, col]`。

- `col` 增大 = **向东**
- `row` 增大 = **向南**（即 `row` 减小 = 向北）
- `cell` = 网格边长（米）

### 2.2 方位角（罗盘方位）

`az_deg`：**0° = 正北，90° = 正东，180° = 正南，270° = 正西**（顺时针）。

### 2.3 方向向量的两个版本（关键）

代码里必须严格区分这两个，混用就会得到 180° 反向的阴影：

```python
sun_direction(az, el)        # 指向太阳的三维单位向量 (dcol, drow, dz)
                             #   dcol = +sin(az)*cos(el)     向东为正
                             #   drow = -cos(az)*cos(el)     向北为负（row 向南增大）
                             #   dz   = +sin(el)

horizontal_direction(az)     # 水平面内沿方位角 az 的二维单位向量
                             #   注意：这是"朝 az 方向看出去"，不是"太阳在 az"
```

**三条铁律**：

1. **ray-marching 要向太阳方向采样**，即用 `-(dcol, drow)` 外推；阴影本身落在太阳的**反侧**。
2. **地平线图存的是"指向太阳方向上的最大仰角"**，因此内部要对 `az + 180°` 取水平方向（或等价地对 `horizontal_direction(az)` 取负）。差这 180°，阴影会画到太阳同侧。
3. **绝不要用 `sun_direction(az, 90.0)` 去取水平方向** —— `cos(90°) = 0`，向量退化成零向量，整个计算**静默失效**（全部返回初始值，不报错）。这是我实际踩过的坑，所以专门抽出了 `horizontal_direction()`。

### 2.4 太阳位置输入

可以是 $(az, el)$，也可以是**亚太阳点经纬度** $(\lambda_s, \phi_s)$。两者互转：

$$\sin(el) = \sin\phi\sin\phi_s + \cos\phi\cos\phi_s\cos(\lambda_s-\lambda)$$
$$az = \operatorname{atan2}\!\big(\sin(\lambda_s-\lambda)\cos\phi_s,\ \cos\phi\sin\phi_s - \sin\phi\cos\phi_s\cos(\lambda_s-\lambda)\big)$$

代码：`sun_az_el_from_subsolar()`。

## 3. A 类：从 DEM 预测阴影

### 3.1 判别式（务必记牢方向）

设本点为 $P$，太阳高度角 $h_s$、方位角 $\phi_s$。沿**指向太阳**的水平方向走 $d$ 米到达 $Q$，则太阳光线在 $Q$ 处的高度为

$$\text{ray}_h = z(P) + d\tan h_s$$

$P$ 处于阴影中，当且仅当**存在某个 $Q$ 的地形高于这条光线**：

$$z(Q) \ge z(P) + d\tan h_s \quad\Longleftrightarrow\quad \underbrace{\arctan\frac{z(Q)-z(P)}{d}}_{\text{地平高度角}} \ge h_s$$

**健全性检查（一定要写进单测）**：平坦地形（$z$ 处处相等）时左边 $=0 < d\tan h_s$，**不产生任何阴影**。我第一版把不等号写反（写成 $\text{ray}_h > z(Q)$），结果**平坦地形 100% 全黑**——这个测试一跑就抓住了。

### 3.2 两个独立实现（本模块都提供了，用于交叉验证）

| 方法 | 函数 | 复杂度 | 换太阳角 |
|---|---|---|---|
| **射线行进** ray-marching | `compute_illumination()` | $O(N_{\text{step}}\cdot N_{\text{pix}})$ | 必须重算 |
| **地平线图** horizon map | `horizon_map()` + `illuminate_from_horizon()` | 预计算 $O(N_{az}\cdot N_{\text{step}}\cdot N_{\text{pix}})$，之后 **$O(N_{\text{pix}})$ 查表** | **不用重算** |

**地平线图的定义**：对每个像素、每个方位角分箱 $m$，预存

$$H(i,j,m) = \max_{d\le d_{\max}} \arctan\frac{z(i+d\sin\phi_m,\ j-d\cos\phi_m) - z(i,j)}{d}$$

之后"太阳是否被挡住"退化为一次比较：`shaded ⟺ h_s < H(i,j,φ_s)`，方位角方向做线性插值。

**实测交叉一致性**（192×192 合成月面，`n_az=72` 即 5° 分箱）：

| 太阳 (az, el) | 射线行进阴影占比 | 地平线图阴影占比 | 像素一致率 |
|---|---|---|---|
| (45°, 8°) | 82.45% | 82.24% | 99.76% |
| (137°, 5°) | 92.29% | 91.90% | 98.97%* |
| (270°, 20°) | 50.79% | 49.93% | 97.88% |
| (313°, 3°) | 87.00% | 86.93% | 99.91% |

\* 该行取自 `make_figure.py` 在 192×192、relief=8 下的输出（其余取自 check 脚本，种子不同）。

**这就是"两个独立实现互证"的价值**：它们是用完全不同的循环结构写的，一致就说明几何真的对了。

### 3.3 必须加的一项：局部坡面朝向（attached shadow）

只算投射阴影（cast shadow）是不够的。**背向太阳的坡面收不到直射光**，这在地球上不明显（有大气散射），在月球上极其显著（无大气，背阳坡直接黑）。做法是算法向与太阳方向的夹角：

$$\cos\theta_i = \frac{-g_x d_{col} - g_y d_{row} + d_z}{\sqrt{g_x^2+g_y^2+1}}$$

$\cos\theta_i \le 0$ 即判为背阳。其中 $g_x = \partial z/\partial \text{东}$、$g_y = \partial z/\partial \text{北}$（注意 $y$ 向北为正，与图像 row 方向相反）。

**实测影响**（`n=160, seed=20261010, az=270°, el=20°`）：

| 配置 | 射线行进阴影占比 | 地平线图阴影占比 | 一致率 |
|---|---|---|---|
| 仅投射阴影 | 49.38% | 50.19% | 40.54% |
| 加局部坡面朝向 | 50.79% | 71.84% | 61.11% |

（该行是修复方向 bug **之前**的数据，仅用于说明"两者都必需"；修复后一致率升到 97.88%。）

**月球极区的量级感**：南极太阳高度角常年只有 1–2°，于是

$$L_{\text{shadow}} = \frac{h}{\tan h_s} \approx \frac{h}{\tan 1.5°} \approx 38\,h$$

**一块 1 m 高的石头能投出约 38 m 长的影子。** 所以在月球极区，"长阴影"不是视觉效果，而是**主导性的可观测性约束**——大片区域会因为阴影而无法观测。

### 3.4 计算优化要点

本模块的全部实现都基于一个技巧：**整图平移代替逐像素循环**。

```python
shifted = _shift_zero(dem, srow, scol, fill=-inf)   # 向量化平移
```

⚠️ **必须用零填充，绝不能用 `np.roll`**。`np.roll` 是**环形回绕**的：位移超过图像尺寸时会出现错误的缠绕，图像边缘的遮挡判断也是假的。`_shift_zero` 就是为此专门写的，越界处填 `-inf`（表示"没有地形遮挡"）。

**另外两个提前退出条件**（对低太阳角场景很重要，因为阴影占比高）：
- 某一步没有任何新像素被遮挡 → 跳过该步；
- 所有像素都已被遮挡 → 整体退出。

## 4. A' 类：太阳位置怎么算

### 4.1 精确做法：SPICE（任务级必用）

标准流程：加载月体固连系姿态内核（`pck`）+ 行星星历内核（`spk`/`bsp`）→ 求太阳相对月球中心的方向 → 转到 `IAU_MOON` 固连系 → 得到**亚太阳点经纬度** → 转到站心系得 $(h_s, \phi_s)$。Python 用 `spiceypy`，教程见 [SPICE 官方文档](https://readthedocs.org/projects/spiceypy/downloads/pdf/latest/) ✅。

⚠️ 我只核验了该文档的出处，**未逐条核对函数签名**；写代码时请以官方文档为准。

### 4.2 教学/仿真做法：低精度解析法

本模块的 `solar_position_analytic()` 与 `subsolar_lonlat_analytic()` 用的是：

- 太阳视黄经的**低精度级数**（Meeus 简化式），
- 月球**卡西尼态自转**（自转周期 = 公转周期 ≈ 27.32166 d，同步自转），
- 月球北极方向近似 $(\alpha_p, \delta_p) \approx (269.9949°, 66.5392°)$。

**精度声明（必须写进论文）**：典型误差 **0.1°–0.5°**，**足以支撑教学与仿真，不足以支撑任务级规划**。差别在哪：任务级要求把**月球物理天平动（libration）**和更高阶的黄经项算进去。

**自检结果**（见 [`check_lunar_shadow.py`](../check_lunar_shadow.py) 第 5 项）：

| 儒略日 | 亚太阳点经度 | 亚太阳点纬度 |
|---|---|---|
| 2451545 (J2000) | 100.39° | 0.02° |
| 2451635 | −168.91° | −0.01° |
| 2460545 | −30.10° | −0.01° |

纬度落在 ±1.6° 内 —— 与月球黄赤交角约 **±1.54°** 一致，这是模型自洽性的证据。另外在南纬 89.5° 处算得太阳高度角 0.44°，符合极区低太阳角的预期。

### 4.3 DEM 的地理参考

`dem_to_lonlat()` 提供最简单的等距投影：`lon = west + col*res_deg`、`lat = north - row*res_deg`。真实产品（LOLA/LROC）请按其附带的投影信息处理，不要用这个近似。

## 5. B 类：从图像提取阴影

### 5.1 判据

月球图像近灰度，阴影的物理特征是：

1. **低亮度**（主判据）；
2. **低饱和度**（彩色相机下有效；灰度相机退化为无效判据）；
3. **边界锐利**（无大气散射 → 阴影边界几乎是阶跃）。

### 5.2 实现：软打分，不要硬与（AND）

本模块把三项合成一个分数，而不是取交集：

$$\text{score} = \underbrace{\text{darkness}}_{\text{主判据}} \times \underbrace{\text{sat\_penalty}}_{\text{颜色旁证}} \times \Big(1 - w_e\,(1-\text{edge\_bonus})\Big)$$

⚠️ **为什么不能硬 AND**（这是实测出来的教训）：真实的月面阴影常常是**大片连通区域**，其内部梯度为零。如果要求"每个阴影像素都必须紧邻强边缘"，召回率会崩掉。实测在 160×160 合成图上：

| 实现方式 | 检出阴影占比 | F1（tol=2 px） |
|---|---|---|
| 硬 AND（亮度 ∧ 饱和度 ∧ 边缘带） | 0.179 | **0.383** |
| 软打分（本模块） | — | **1.000** |

真值阴影占比 0.855 —— 硬 AND 把大片阴影区域整体丢掉了。**边界锐利度是用来消歧的旁证，不能作为必要条件。**

### 5.3 光照不变特征

`illumination_invariant()` 做局部亮度归一化 $I_{\text{norm}} = I / (I_{\text{local}} + \epsilon)$，用来压制跨光照的外观差异。这是"光照鲁棒检测器"的标准预处理，直接服务于综述 §10.3。

**更物理的做法**是光度归一化（photometric normalization），但**月球必须用 Hapke 类光散射模型，不能用朗伯假设**。

### 5.4 消歧：把 B 和 A 结合起来

**纯阈值的失效模式**：低反照率物质（暗色月海、暗色晕、玻璃质碎屑）会被误判为阴影。

**正确的消歧方式**：用 A 类（DEM 预测）给出"几何上应该在哪里有阴影"的**先验**，与 B 类（图像低亮度）做一致性检验：

- 图像暗 **且** DEM 预测阴影 → 真阴影；
- 图像暗 **但** DEM 预测被照亮 → 低反照率物质（**这才是你真正想找的科学目标**）；
- 图像亮 **但** DEM 预测阴影 → DEM 误差或配准问题。

**第三行反过来就是一个免费的创新点**：这个"矛盾图"本身可以当作科学目标候选生成器——因为它标记的正是"DEM 解释不了的暗斑"。

## 6. C 类：用阴影反推几何与太阳参数

### 6.1 阴影长度 ↔ 物体高度

$$h = L_{\text{shadow}}\cdot\tan h_s \qquad\Longleftrightarrow\qquad h_s = \arctan\frac{h}{L_{\text{shadow}}}$$

`shadow_length_to_height()` / `estimate_sun_elevation_from_shadow()`。互逆性已在 9 组参数上验证，误差 < 1e-6。

### 6.2 无星历估计太阳方向（月球车特别实用）

**巡视器自己就是已知尺寸的标定物。**

- 从图像量出车体投影长度 + 已知车体高度 → 反推 $h_s$；
- 投影方向直接给出 $\phi_s$。

这正是火星车团队在星上确认太阳方位的手段。**可以把这一步做成巡视器的开机自检流程**：如果反演出的 $(h_s,\phi_s)$ 与星历预测偏差超过阈值，说明相机安装矩阵或姿态估计有问题。

### 6.3 由阴影掩膜反演太阳几何（闭环自检）

`recover_sun_geometry()` 在 $(az, el)$ 网格上搜索，使**预测阴影掩膜与实际阴影掩膜 IoU 最大**。用粗搜（5°）定位峰值 + 邻域细搜（2°/0.5°）。

**实测结果**：

| 真值 (az, el) | 反演 (az, el) | 最优 IoU | 次优方位 IoU | 间隔 |
|---|---|---|---|---|
| (60°, 6°) | (61°, 6.0°) | 0.996 | 0.987 (@63°) | **0.0089** |
| (225°, 12°) | (226°, 12.0°) | 0.994 | 0.992 (@224°) | **0.0021** |

**高度角几乎完美，方位角只有 ~1° 精度，而且最优与次优的差距不到 0.01** —— 这说明：

> ⚠️ **单张阴影掩膜对太阳方位角是"简并"的（ill-posed），这不是 bug，是方法固有的可辨识性问题。**

原因很直观：投射阴影的**形状主要由太阳高度角决定**，对方位角的敏感度低得多（方位角主要影响阴影的**朝向**，而朝向在"哪片区域是阴影"这个二值掩膜里只体现为边界细节）。

**三条对策**（写论文时这是很好的"方法局限性 + 解决方案"素材）：

1. 用 IoU 锁定高度角（可靠），方位角另找约束；
2. 用**巡视器自身阴影的方向**约束方位角（几何上最强的单条线索）；
3. **多帧联合反演**：太阳方位角随时间单调变化（月球上变化很慢），多时刻联合可以打破简并。

### 6.4 光度法（photoclinometry / shape-from-shading）

从亮度梯度反推地表坡度，用于**补足 DEM 在阴影区无高程**的问题。月球必须用 Hapke 类光散射模型，带多相位的实现见 [Multiphase photoclinometry as applied to the lunar photometry with LROC NAC data](https://www.sciencedirect.com/science/article/abs/pii/S0032063324000783) ✅（出处核验）。相关链路可见[基于反射率建模的月面 DEM 构建](https://ui.adsabs.harvard.edu/abs/2014AdSpR..53.1735G/abstract) ✅。

## 7. 选型表

| 你的场景 | 选哪个 | 理由 |
|---|---|---|
| 一次性算某太阳角的阴影掩膜 | **射线行进** `compute_illumination()` | 20 行核心逻辑，够用 |
| 要遍历多太阳角/多日期（算观测窗口、判 CIR/PSR） | **地平线图** `horizon_map()` | 预计算一次，之后每次换角度免费 |
| 大范围/实时（车载） | 地平线图 + 球谐/傅里叶压缩，或 GPU | 见 [HPG 2025](https://highperformancegraphics.org/untracked/2025/presentations/Pa5_2_Fast%20Planetary%20Shadows%20using%20Fourier-Compressed%20Horizon%20Maps.pdf) ✅ |
| 只有影像、没有 DEM | **光照不变特征** 或 **巡视器自标定** | B2 / C2 |
| 需要真值标签 | 射线行进 + 地平线图**互证** | 两者一致才可信 |
| 要补阴影区高程 | **光度法 + Hapke** | C4 |

## 8. 六个必须知道的坑（踩过并有实测数据）

### 8.1 方位角符号 —— 四个 bug 里的三个

**症状**：阴影落在太阳同侧；或两种实现永远对不上。

**为什么难发现**：整体看"有阴影、形状也像"，肉眼看图不易察觉；而且如果只做单实现测试，它会自洽地错下去。

**怎么钉死**：用**解析算例**。南北走向的山脊（`dem[:, 100] = 10`），太阳在正西（az=270°）：

- 山脊**西侧**（col 100–200 方向是东侧，注意）应被遮挡，地平高度角 = atan(10/50) = **11.31°**；
- 山脊东侧应无遮挡。

实测：`Hmap[正西分箱, 100, 150] = 11.31°`、`Hmap[正西分箱, 100, 50] = 0.00°`，射线行进阴影落在 col 101–200。**这一条测试胜过一千行代码审查。**

### 8.2 `np.roll` 的环形回绕

`np.roll` 在边缘会绕回来，产生虚假遮挡。必须零填充（本模块 `_shift_zero()`）。**健全性测试：平坦地形必须 100% 全亮。** 实测阴影像素 = 0。

### 8.3 `sun_direction(az, 90°)` 取水平方向 —— 零向量，静默失效

`cos(90°) = 0` → 方向向量为零 → 所有偏移取整为 0 → 循环体被 `continue` 跳过 → **整个地平线图全返回初始值 −90°**，而代码**不报任何错**。

实测症状：地平线图全图 max = −90°，所有像素都判为"被照亮"，于是射线行进（80% 阴影）与地平线图（41% 阴影）对不上。

**教训**：方向向量一定要单独抽函数（`horizontal_direction()`），不要在调用处拼参数。

### 8.4 硬 AND 毁掉召回率

见 §5.2。实测 F1 从 1.000 掉到 0.383。

### 8.5 方位角简并（不是 bug，是方法的性质）

见 §6.3。**论文里必须承认这一点**，否则审稿人一问就露。

### 8.6 DEM 算出的阴影掩膜不能直接当训练标签

三个原因：

1. **分辨率不匹配**：LOLA 最好约 5 m/像素，与影像尺度差 1–2 个数量级，小尺度阴影**根本渲染不出来**；
2. **阴影区本身无高程测量**：DEM 在那里是插值出来的，**误差最大**——正好在最需要准确的地方最不准；
3. **配准误差 + 边界不一致**：合成阴影与真实阴影不可能逐像素对齐。

**因此评估必须用容差 F1**（预测与真值各自膨胀 tol 像素）。实测"整体错位"对评分的影响：

| 配准错位 | F1 (tol=3 px) | IoU（无容差） |
|---|---|---|
| 0 px | 1.000 | 1.000 |
| 2 px | 1.000 | 0.903 |
| 4 px | 0.995 | 0.852 |
| 8 px | 0.976 | 0.806 |
| 12 px | 0.962 | 0.776 |

**结论**：无容差的 IoU 测的**主要是配准误差，不是检测性能**。用容差 F1，8 像素的错位只让分数掉 2.4 个百分点。

**附带证据**：本模块专门验证了"容差不会把完全不同的掩膜判为高分"——互补掩膜的 F1(tol=1) = 0.111，安全。
